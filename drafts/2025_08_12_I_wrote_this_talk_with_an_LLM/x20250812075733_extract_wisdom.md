# 摘要

Hadley Wickham 分享了一份关于大型语言模型（LLM）的实用指南，讨论了如何利用它们赋能自己，并揭示了它们在现实世界中的机遇和挑战。

# 想法：

- 应对 AI 带来的生存焦虑，一个有用的方法是做一件小事，让世界变得更好。
- 大型语言模型（LLM）颠覆了我们对电脑能力的传统认知，擅长模糊任务而非精确计算。
- LLM 时而惊人地智能，时而又惊人地愚蠢，这导致人们对它产生矛盾情绪。
- 我们不能因为 LLM 在简单问题上犯错就放弃它们，这并非它们的设计初衷。
- 今天的编程新技能之一，是学会何时接受或忽略 AI 提供的行内代码补全建议。
- LLM 可以将各种非结构化数据，如文本、图像、音频等，转化为整洁的矩形数据。
- 将 LLM 的输出视为带有测量误差的数据，这与统计学的核心思想不谋而合。
- "工具调用"机制让 LLM 能够与外部世界互动，弥补了其无法获取实时信息的缺陷。
- 一个工具的本质是一个函数加上一些元数据，用以告知 LLM 其功能和用法。
- 智能体是一个被赋予"读取"和"改变"世界状态两类工具的聊天机器人。
- 目前智能体领域的安全状况堪忧，被称为"YOLO 模型"，即后果自负。
- LLM 在"翻译"任务上表现出色，例如将伪代码转换为任何特定编程语言。
- 将自然语言描述转换为复杂的正则表达式，是 LLM 翻译能力的一个极佳应用场景。
- LLM 能将视觉概念（如手绘草图）"翻译"成可执行的代码，极大提高了原型制作效率。
- "降低启动能量"是 LLM 的另一大优势，它帮助我们克服开始任务的心理障碍。
- 看到 LLM 生成的糟糕初稿，会激发人类强烈的修正欲望，从而轻松开始工作。
- LLM 能让你快速进入不熟悉的领域，达到"足以构成威胁"的水平，无论好坏。
- 相比个人，大型企业对数据隐私的担忧较小，因为它们的数据本就在云端。
- 担心工作被 AI 取代？或许管理者们更应该感到焦虑，因为他们的工作更易被 AI 替代。
- 如果有人强迫你从 R 转向 Python，你可以反驳说我们正处在"后语言时代"。
- 对抗 AI 威胁论的一个对冲策略是学习一门手艺，比如管道工或电工。
- 使用 LLM 是一项需要学习和投资的新技能，不可能一蹴而就。
- 即使对 AI 有道德上的疑虑，也必须参与其中，否则你将被时代抛在后面。
- LLM 不会让你成为 10 倍程序员，但提升 10% 或 20% 也是巨大的进步。
- 面对感到无力或失控的未来，去做一件小事，做一个小实验来理解它。
- 尽管存在炒作，但 LLM 距离取代数据科学家或软件工程师还有很长的路要走。
- 面对技术变革，最佳防御是主动出击，积极学习和利用新技术。
- "吃豆人规则"鼓励社交场合留出空位，方便新人加入，营造包容氛围。
- 即使 LLM 的艺术创作取代了免版税图片，我们仍应支持并购买真人艺术家的作品。
- 编程中最难的挑战之一，是避免过早锁定于第一个看似可行的解决方案。

# 见解：

- 与其恐惧 AI，不如通过做小实验来赋能自己，重新获得对未来的掌控感。
- LLM 不擅长精确任务，但擅长模糊任务，这要求我们改变评估其价值的方式。
- "工具调用"将 LLM 从孤立大脑变成可与世界交互的系统，开启了智能体时代。
- 当前智能体安全实践极为初级，这既是巨大机遇，也是亟待解决的工程挑战。
- LLM 的核心价值之一是"降低启动能量"，帮助我们克服创造和探索的心理障碍。
- 人类在 AI 时代的角色，是更高层次的监督者、评判者和精炼者，而非被取代。
- 将 LLM 的输出视为带误差的数据，并用统计学方法处理，是人机协作的高级范式。
- 对 AI 的恐惧源于未知，通过亲身实践和学习，能消除无力感并发现其潜力。
- 我们正进入"后语言时代"，编程语言的壁垒将被 LLM 的翻译能力逐渐打破。
- 专业化工具在特定领域仍有巨大价值，世界不需要统一的通用编程语言。
- LLM 的出现，迫使我们重新思考学习的方式，以及人类知识与技能的本质。
- 不要完全信任 LLM 的产出，但要利用它摆脱停滞，向前迈进并从错误中学习。

# 事实：

- 大型语言模型（LLM）在基本的计数和算术任务上表现糟糕，且结果是随机的。
- 新版本的 LLM 修复了旧问题，但这通常是靠调整提示而非模型本身变得更智能。
- LLM 的回答总是看似合理，且很少承认自己不知道或不确定，缺乏谦逊。
- 通过提供 JSON Schema，可以强制 LLM 输出结构化的、可直接被程序使用的数据。
- 工具调用机制的本质是 LLM 请求本地环境执行代码，而非在云端运行。
- 大部分大型企业的数据已存储在云服务商处，因此使用同平台 LLM 的隐私风险较低。
- 个人使用 LLM 的环境影响，远小于一次飞行所产生的碳排放。
- Google 的 Gemini 模型因市场份额落后，提供了非常慷慨的免费使用额度。
- R 语言在数据科学领域的代码存量足够大，LLM 可以很好地生成相关代码。
- R 社区的"吃豆人规则"提倡在社交时留出缺口，方便新人加入交谈圈。
- 使用 API key 并花费 5 美元，可以支持相当长时间的 LLM 实验和探索。
- 一个名为`vital`的 R 包正在开发中，旨在将统计模型评估原则用于评估 LLM。
- 一个名为`BTW`的工具能让 LLM 读取最新的 R 文档，以解决其知识过时的问题。
- 担心工作被 AI 取代的软件工程师，也许应该看到管理者面临着更大的被替代风险。
- Posit 公司员工在填写公司名称时，使用了多种不同的变体，展现了数据不一致性。
- LLM 生成的艺术作品，可以作为免版税图库的替代品，但不能取代真人艺术创作。
- 开发者会因不想让 GitHub issue 列表翻页而快速解决问题，这是一种有趣的心理驱动。
- 大会组织者使用 R 代码生成了北卡罗来纳州地图形状的"黑客墙"用于社交。

# 一句话总结：

停止恐惧，开始实验：将 LLM 作为降低启动能量的工具，去探索你未知的领域。

# 建议：

- 如果你对未来感到无力，去做一件小事，做一个小实验来重新获得掌控感。
- 不要因为 LLM 在简单任务上犯错而放弃它，要用它来解决它擅长的模糊问题。
- 将 LLM 的输出视为带有测量误差的数据，并使用你的专业知识和工具去验证它。
- 尝试使用"工具调用"来扩展 LLM 的能力，让它能与你本地的环境和数据互动。
- 利用 LLM 来降低启动能量，让它为你生成糟糕的初稿，然后你来修正和完善。
- 探索不熟悉的领域时，用 LLM 快速上手，它能让你很快达到"足够危险"的水平。
- 如果有人强迫你转换技术栈，你可以用"我们正处在后语言时代"的论点来回应。
- 为了对冲 AI 带来的不确定性，不妨去学习一门与双手相关的实用手艺。
- 如果你对 AI 有道德或伦理上的顾虑，更应该参与其中，而不是选择忽视它。
- 不要期望 LLM 让你成为 10 倍程序员，能提升 10-20% 就已经是巨大的胜利。
- 注册一个 API key，投入少量资金（如 5 美元），亲手体验 LLM 的真正能力。
- 在社交场合中，记得践行"吃豆人规则"，为新朋友留出加入谈话的空间。
- 面对看似棘手的问题，先让 AI 去尝试，你可能会发现问题并没想象中那么难。
- 不要过早地满足于 LLM 给出的第一个解决方案，要批判性地审视和测试它。
- 支持并购买真人艺术家的作品，即使 AI 可以生成免费的替代品。
- 在会议期间，选择一个议程并坚持听完，而不是在不同会场间频繁穿梭。
- 主动分享你在社交媒体上的学习和参会体验，并使用推荐的话题标签。
