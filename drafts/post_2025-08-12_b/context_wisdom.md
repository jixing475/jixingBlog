# 摘要

Hadley Wickham 和 Wes McKinney 讨论了开源、跨语言协作、Positron IDE、以及 AI 在数据科学中的实际应用，分享了他们从职业生涯开始到现在的见解。

# 想法：

- 职业生涯始于偶然，在保密的代码环境中萌生了对开源世界的向往和追求。
- 开源不仅是分享代码，更是将思想和可用工具带给世界的一种高效方式。
- 成熟的开源项目很难进行大刀阔斧的改革，因为必须优先考虑现有用户的代码稳定性。
- Polars 等新兴框架的优势在于没有历史包袱，可以从头构建更简洁、高效的 API。
- Polars 的 API 在设计上更接近 R 的 dplyr，比传统的 Pandas 更简单。
- 跨语言文档的核心挑战在于，如何为只懂一种语言的用户提供无缝的切换体验。
- Quarto 的 tab sets 功能，允许在同一文档中为 R 和 Python 用户提供不同代码块。
- Positron 的目标是为多语言数据科学提供经典的四窗格布局，提升 Python 用户体验。
- Positron 构建于 VS Code 开源代码库之上，通过大量定制来支持 R 和 Python。
- 多语言（Polyglot）策略不仅限于 R 和 Python，更是为未来任何数据科学语言奠定基础。
- 像 Parquet 这样的文件格式，正在推动数据存储与计算引擎的"解耦"，提升灵活性。
- LLM 在编程中的主要价值，体现在处理不熟悉领域和解决"空白页"问题上。
- AI 助手可以通过获取数据科学环境中的上下文（如列名）来提供更精准的建议。
- RAG（检索增强生成）在 R 语言生态中的缺失，是目前与 Python 相比的一个短板。
- 使用 DALL-E 等图像生成模型，可以作为设计 logo 和进行视觉头脑风暴的有效工具。
- AI 在重构代码方面表现出色，能自动识别模式并完成繁琐的、重复性的修改工作。
- ChatGPT 等工具在生活规划类任务上的表现，通常优于充满广告和无关信息的搜索引擎。
- Python 社区庞大且分散，而 R 社区更中心化，这导致了两者生态文化的差异。
- CRAN 要求开发者对兼容性负责，而 PyPI 将解决依赖冲突的责任转移给了用户。
- 拥有一个紧密协作的开发者社区，是 R 语言生态系统（如 Tidyverse）凝聚力强的关键。
- 一个小而专注的团队，其成就往往能超越拥有百名工程师的大型创业公司。
- 开源数据库项目（如 DuckDB）的协作精神，正在改变传统数据库社区的封闭文化。
- 像 Typst 这样的项目，正以小团队之力挑战 LaTeX 等长期存在且复杂的系统。
- AI 领域的炒作周期终将平息，届时将出现整合，让工具开发者能更专注地提升效率。
- 从自己精通的领域，勇敢地跨入一个全新领域从头学起，是一种非凡的品质。
- 成功的开源项目会形成"引力井"，吸引社区围绕其构建兼容且一致的工具生态。

# 见解：

- 成熟的开源项目面临着创新者困境：必须在服务现有用户和进行颠覆性创新之间取得平衡。
- 语言生态的凝聚力，不仅取决于社区大小，更源于开发者间积极的对话与协作文化。
- 中心化的包管理（如 CRAN）给开发者带来痛苦，却为用户提供了更稳定的体验。
- AI 的最佳应用场景，是作为起点和头脑风暴的工具，而非追求百分百准确的终点。
- 未来最高效的 AI 助手，将能结合代码上下文和数据环境的元数据来提供建议。
- 数据存储与计算的解耦是未来趋势，它让用户能用多种引擎处理同一份数据。
- 真正伟大的成就，往往来自小而专注的团队，而非单纯依靠庞大的工程师数量。
- 跨语言协作的未来，在于构建共享的词汇、工具集和数据约定，以降低认知摩擦。
- 成为一个领域的专家后，敢于在另一个领域重新成为新手，是持续成长的关键。
- 即使有 AI 辅助，人类在编程中的核心价值依然是批判性思维和对最终结果的编辑。
- 社区文化差异（R vs Python）直接影响了工具的演进路径和用户体验。

# 习惯：

- 在周末或业余时间，通过烹饪（如长时间炖菜）和调制鸡尾酒来放松和社交。
- 坚持练习瑜伽，尽管从未和同事一起练习过，这是一种保持身心健康的爱好。
- 对钩针编织（crochet）产生兴趣，并从易于上手的工具包（如 Woobles）开始。
- 使用 AI（如 ChatGPT）来规划旅行，例如创建一个避开游客景点的京都徒步路线。
- 当在不熟悉的编程领域（如 JavaScript）工作时，会利用 AI 来辅助编写代码。
- 利用 AI 的重构能力，在识别出代码模式后，通过多次按 Tab 键快速完成修改。
- 曾经花费大量时间在 Google 和 Stack Overflow 上搜索，现在用 AI 来解决问题。
- 不会百分百信任 AI 的输出，但会利用它来获得一个接近完成的起点（90%）。
- 在开始一个新项目或新功能时，会使用 AI 来生成模板代码以克服"空白页"的困难。
- 对于不准确也无妨的任务（如寻找食谱），会优先使用 AI 而非传统的搜索引擎。
- 会选择性地使用工具，并忽略掉大量噪音，专注于少数能提升效率的工具。
- 面对复杂问题时，会与社区（如内部会议）进行讨论，以获得不同视角的想法。
- 会持续关注并试用新的 AI 工具（如从 Copilot 切换到 Continue），以保持领先。
- 在设计软件包的 logo 时，会先用 DALL-E 进行头脑风暴，再与专业设计师合作。

# 事实：

- Wes McKinney 是 Pandas、Apache Arrow 和 IBIS 项目的共同创造者。
- Hadley Wickham 是 Tidyverse（包括 ggplot2 和 dplyr）等 R 包的创建者。
- Woobles（钩针编织工具包）的创始人之一，曾是 Google 的一位数据科学家。
- Positron 是一个基于 VS Code 开源代码库构建的多语言数据科学 IDE。
- Polars 和 DuckDB 等项目，使得在单台机器上处理曾经的"大数据"成为可能。
- R 的包管理系统 CRAN，要求开发者确保其包不破坏其他包的兼容性。
- Python 的包管理系统 PyPI，将解决依赖兼容性的责任主要留给了用户。
- 数据存储和计算正在"解耦"，Parquet 等格式允许数据被多个计算引擎访问。
- `rpy2`可用于在 Python 中调用 R 代码，而`reticulate`可在 R 中调用 Python 代码。
- Quarto 的`quartodoc`工具，正在帮助许多 Python 项目构建更高质量的文档网站。
- R 语言的包通常有 vignettes（小品文），即长篇幅的教程，这在 Python 中较少见。
- Plotnine 是 ggplot2 的一个 Pythonic 移植版本，旨在提供相似的 API 体验。
- Ibis 是一个受 dplyr 启发的、可移植的 Python 数据框 API。
- Typst 是一个旨在替代 LaTeX 的高质量排版系统，由一个很小的团队开发。
- Continue 是一个开源的 VS Code 扩展，可作为 Copilot 的替代品使用。

# 一句话总结：

通过跨语言协作和务实的 AI 应用，我们能构建更强大、更统一的数据科学工具生态。

# 建议：

- 当为 R 和 Python 用户创建文档时，使用 Quarto 的 tab sets 功能进行无缝切换。
- 如果你是 R 用户并想在 Python 中找到类似体验，可以尝试 Plotnine 和 Ibis 项目。
- 在不熟悉的编程领域，利用 AI 助手生成初始代码，以克服"空白页"的恐惧。
- 使用 AI 进行头脑风暴和生活规划，尤其是在那些不要求百分百准确的探索性任务中。
- 对于大型数据集，优先考虑使用 Polars 或 DuckDB 在单机上进行高效分析。
- 不要害怕在精通一个领域后，勇敢地进入新领域，从头开始学习是成长的关键。
- 参与到你所使用的开源社区中，积极的对话与协作能催生出更好的工具生态。
- 如果你的团队同时使用 R 和 Python，投资于构建共享的数据格式和工具集。
- 尝试使用 Continue 等开源 AI 助手，你可以插入自己的 API 密钥，获得更可控的体验。
- 关注数据存储与计算的解耦趋势，利用 Parquet 等格式提高数据处理的灵活性。
- 将 AI 用于代码重构等重复性任务，它可以显著提高你的工作效率和生产力。
- 即使有强大的 AI 工具，也要保持批判性思维，手动验证和编辑最终的产出。
- 鼓励你的 Python 项目也设计一个炫酷的 logo，这能增强社区的凝聚力。
- 在构建混合语言应用时，先选择一个主要的前端框架（如 Shiny），再通过工具调用另一种语言。
